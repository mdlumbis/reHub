# reHUB

Master's school project built by 2 people. A web app that connects rehabilitation patients in the Philippines with providers (physiatrists, PTs, OTs, SLPs, rehab clinics), including HMO / PhilHealth coverage matching.

## Stack
- Next.js 16 (App Router, `src/` dir, TypeScript). `cacheComponents` is OFF in next.config.ts on purpose; do not add `"use cache"`. Read `node_modules/next/dist/docs/` before using unfamiliar APIs: this version differs from older Next.js (e.g. `middleware.ts` is now `src/proxy.ts`, `params`/`searchParams` are Promises).
- Tailwind CSS v4. Design tokens live in `src/app/globals.css` under `@theme`.
- Supabase (Postgres + Auth) via `@supabase/ssr`.
- Icons: `lucide-react`. Font: Inter (`@fontsource-variable/inter`).
- Deployed on Vercel.

## Ownership (avoid editing the other person's area without asking)
- **Person A, patient side:** `src/app/(site)/search`, `coverage`, `patient/**`, `(auth)/register` (patient form), clinic profile, appointment booking.

## Conventions
- Server Components by default. Add `"use client"` only for state, effects, or event handlers.
- Forms: Server Actions + `useActionState`. For long forms, submit via `onSubmit` + `startTransition` so fields aren't cleared on validation errors (see `src/app/(auth)/register/RegisterView.tsx`). Validate on the server and return `fieldErrors`.
- Supabase in server code: `await createClient()` from `@/lib/supabase/server`. In client code: `createClient()` from `@/lib/supabase/client`.
- Use theme colors only: `brand`, `brand-hover`, `brand-soft`, `brand-mist`, `ink`, `body`, `muted`, `line`, `canvas`. No raw hex in components.
- Visual style: white cards, `rounded-2xl border border-line`, primary buttons `h-12 rounded-lg bg-brand text-white font-semibold`. Match the Figma mockups.
- Components: PascalCase files. Routes: kebab-case folders.
- Placeholder screens use `<ComingSoon />`. Replace it when building the real page.
- Every new table gets RLS enabled with explicit policies.
- Never commit `.env.local`.

## Roles & auth
- Sign-up passes all form fields in `options.data`; the `handle_new_user` DB trigger creates `profiles` + `patient_details` or `provider_details`.
- `profiles.role` is `patient` or `provider`. `profiles.username` is the "User ID": generated by the DB at sign-up from first + last name (`generate_username`, e.g. `juan.delacruz`, `juan.delacruz2`). Users never type it.
- `/patient/**` requires a patient, `/provider/**` requires a provider; logged-in users are sent away from login/register (all in `src/lib/supabase/proxy.ts`).
- After login: patients go to `/` (homepage, logged-in nav), providers to `/provider` (dashboard). See `ROLE_HOME` in `src/lib/types.ts`.
- Providers start with `verification_status = 'pending'`; only an admin (SQL) can change it.

## Database (Supabase, see `supabase/migrations/`)
| Table / function | What it holds | Who can read / write |
|---|---|---|
| `profiles` | every user: role, names, username (User ID), contact, location | self |
| `patient_details` | valid ID type/number (private) | self |
| `provider_details` | profession, specializations, headline, about, credentials, years, visit_modes, PRC no./expiry, `*_status` verification | self; `*_status` admin only |
| `public_providers` (view) | safe columns of **verified** providers only | anyone |
| `clinics`, `provider_clinics` | clinic name/address/lat-lng, which provider practises where + schedule text | anyone reads; provider manages own; `address_verified` admin only |
| `services` | per-provider services: name, duration, starting fee | anyone reads; provider manages own |
| `coverage_options`, `provider_coverage` | PhilHealth packages, GL/DSWD, HMOs; which a provider accepts | anyone reads; provider manages own |
| `locations` | city name → lat/lng (same list as `LOCATIONS` in options.ts) | anyone |
| `availability_slots` | bookable times (`is_booked`) | anyone reads; provider manages own |
| `appointments` | bookings: patient, provider, slot, service, coverage, quoted fee, status | patient + provider read; provider updates `status` only |
| `patient_records` | provider's own patient list (MRN auto) | owner provider; referral recipients read |
| `referrals` | 7-field referral, `to_profession` and optional `to_provider_id`, status | sender manages drafts; recipient reads |
| `search_providers(...)` | search + filters + distance ranking + earliest slot + min fee | anyone (rpc) |
| `book_appointment(...)` / `cancel_appointment(id)` | the only way to create/cancel bookings | logged-in patient / either party |
| `respond_to_referral(id, accept)` | recipient accepts/declines | recipient |

- Call functions with `supabase.rpc("search_providers", { p_location: "Makati City, Metro Manila" })`.
- All fees are **starting fees**; always show "final amount set on the day of treatment".
- Demo data: `supabase/seed/demo_data.sql` (8 verified providers, fake `@demo.rehub.test` emails, can't log in). Re-run it to top up slots for the next 14 days.
- To verify a provider: `update provider_details set verification_status='verified', prc_status='verified' where profile_id = '...';`
